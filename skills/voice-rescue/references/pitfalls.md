# Pitfalls already hit on real recordings, and the guard for each

Every item is a mistake that was actually made while cleaning real recordings by hand. Each one is
now a guard in the code or a test in `tests/`.

| # | What went wrong | Guard |
|---|---|---|
| 1 | **A false win measured on pauses.** The echo tail in the pauses after words dropped from −7 to −30 dB, yet the listener heard "talking from a bathroom". The echo lives inside the words. | Quality is measured with SRMR and DNSMOS on VAD speech windows, never on pause tails (`metrics.py`, `vad.speech_windows`). |
| 2 | **The agent cannot hear.** "Sounds good" was written about audio nobody had listened to. | The report says "measured, not listened to" and ships before/after probes at equal loudness (`report.listening_probes`). The ear outranks the numbers. |
| 3 | **SRMR is not a universal "not worse" gate.** On an already dry close mic, SRMR fell after restoration (12.4 → 11.4, 10.8 → 9.3) while speech quality rose and the piece sounded fine. | For inputs with SRMR ≥ 10 the gate is an absolute floor (SRMR ≥ 9), not a comparison with the input (`verify.gate_quality`). |
| 4 | **Sidon squeezed time by 5.6 ppm (~20 ms per hour).** Root cause: the decoder returns `frames × 960 − 26` samples, and the reference recipe glues 96 s chunks without compensating, losing 26 samples per chunk. On top, the decoder output sits 7.375 ms after its input. | Chunks are decoded with 3 s of real context on both sides and cropped to exactly `frames × 960` samples; the constant latency is removed; seams get a 10 ms crossfade inside the shared context (`engines/sidon.py`). Tests: exact length, no drift over an hour, no click at seams. |
| 5 | **Filter delays.** ffmpeg `firequalizer` shifts audio by its `delay` even with `zero_phase` in a WAV; `alimiter` without `latency=1` adds ~2 ms. | Timbre matching uses a linear-phase FIR with its delay removed in numpy (`match.apply_fir`); the limiter always has `latency=1`. Sync is tested after every stage. |
| 6 | **Mono → dual-mono stereo reads +3 LU** in EBU R128. | Loudness is measured on the final stereo file; true peak (not sample peak) is checked (`master.master`, `verify.gate_loudness`). |
| 7 | **Whisper invents text on quiet stretches** ("Subtitles by…", "To be continued…"); a glossary prompt on a long silent start made faster-whisper loop. | VAD on, `condition_on_previous_text=False`, no prompt, and each recognised segment must sit over audio louder than the pause floor (`asr.transcribe`). |
| 8 | **Broken environment.** A Homebrew Python could not load `pyexpat`, so pip and uv refused to install; macOS wiped a venv in `/private/tmp` after three days; model downloads crawled at 0.3 MB/s. | The launcher uses a uv-managed Python 3.12 and keeps the environment in the per-user data folder; downloads resume, show progress, time out and retry (`install.py`). |
| 9 | **zsh scripts were fragile**: `echo =====` fails (`=cmd` expansion), `$OFF:linear` is read as a modifier. | Everything is Python; ffmpeg is always called with an argument list, never through a shell. |
| 10 | **Cutting what nobody asked to cut.** A track trimmed to an edit plan could not be laid under the video. | The deliverable has the source length and start unless a trim is requested; the sync gate checks the exact sample count. |
| 11 | **Disk.** Intermediate files of a one-hour session took 3.2 GB on a 94% full disk. | Free space is checked before heavy stages; intermediates are deleted after a successful run; the expensive Sidon output is cached by the exact decoded input, so a rebuild takes minutes. |
| 12 | **A compressor brought the room back.** In the first version SRMR after the compressor fell below the untreated input. | The mix has no compressor. |
| 13 | **Clocks and file names lie.** A recorder clock was 4 hours off; camera clips had ~2 s gaps between files; the recorder ran 6.1 ppm fast. | Sources are matched by the speech envelope (own session ~0.98, a foreign one 0.2-0.3) and aligned by GCC-PHAT on the direct sound (the envelope of an echoey camera is pulled late by the echo); drift is fitted over many windows of a long enough span and removed by exact resampling (`align.py`). |
| 14 | **A clean mic glued to restored parts sounded different at the seam** (background texture changed). | When parts are glued, the clean source also goes through Sidon (`glue_with_sidon`), and timbre is matched in third-octave bands. |
| 16 | **Memory.** With the reference recipe's 96 s chunks, Sidon took 12-16 GB on CPU and froze a 36 GB machine when other heavy work ran next to it. | 30 s chunks and a 3 s windowed decoder (peak about 4.5 GB, same quality); free memory is checked before the run and before every chunk; restoration runs in its own process, so its memory is returned before the mix (`memory.py`, `engines/sidon.py`). |
| 15 | **Envelope sync against a very echoey input is not trustworthy** (reverb smears the input envelope; individual windows scatter 1-8 ms). | The sync gate reports "not verified" with the spread instead of a false pass or fail; the engine delay itself is proven on clean and synthetic-echo speech in the benchmark. |
