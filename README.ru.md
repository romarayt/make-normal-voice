# voice-rescue

**Скилл для ИИ-агентов: любая запись речи → дорожка для монтажа, звучащая как с близкого
подкаст-микрофона. Локально, с замерами вместо «звучит хорошо».**

[English version](README.md)

Звук камеры с эхом комнаты, встроенный микрофон ноутбука, запись экрана, шумная петличка, несколько
устройств одной съёмки: скилл меряет каждую дорожку, одной строкой объясняет маршрут, восстанавливает
голос нейросетью [Sidon](https://huggingface.co/sarulab-speech/sidon-v0.1), сводит без компрессора
в −16 LUFS, а потом **проверяет** итог (качество, слова, голос, синхрон до 1 мс, громкость, стыки)
и доправляет то, что не прошло. Звук не покидает ваш компьютер.

Работает в **Claude Code** (плагин или папка скилла), в **Codex** (папка скилла) и как обычная
командная строка.

## Пример

Открытая фраза (LibriTTS-R, CC BY 4.0), сыгранная в настоящей небольшой комнате через дальний
микрофон, с шумом комнаты и на -38 LUFS, как звук камеры (подробности в
[docs/samples](docs/samples/ATTRIBUTION.md)):

| | DNSMOS OVRL | DNSMOS BAK | громкость |
|---|---|---|---|
| до ([before.mp3](docs/samples/before.mp3)) | 3,11 | 4,00 | -38 LUFS |
| после ([after.mp3](docs/samples/after.mp3)) | 3,49 | 4,17 | -16 LUFS, -1,5 dBTP |

Слова не изменились (0 из 45 уверенно распознанных), голос тот же (сходство 0,91), длина точная.
Пробы — одни и те же 30 секунд одинаковой громкости. Спектрограммы:
[до](docs/samples/spectrogram_before.png) · [после](docs/samples/spectrogram_after.png).


## Установка

Нужны macOS или Linux, [ffmpeg](https://ffmpeg.org) и [uv](https://docs.astral.sh/uv/). При первом
запуске скачивается около 1 ГБ Python-пакетов и 1,5 ГБ моделей (скилл спрашивает один раз).

**Claude Code, плагином** (внутри Claude Code):

```
/plugin marketplace add romarayt/voice-rescue
/plugin install voice-rescue@voice-rescue
```

или из терминала: `claude plugin marketplace add romarayt/voice-rescue && claude plugin install voice-rescue@voice-rescue`.

**Claude Code или Codex, папкой скилла:**

```bash
git clone https://github.com/romarayt/voice-rescue ~/.local/share/voice-rescue-src
ln -s ~/.local/share/voice-rescue-src/skills/voice-rescue ~/.claude/skills/voice-rescue   # Claude Code
ln -s ~/.local/share/voice-rescue-src/skills/voice-rescue ~/.agents/skills/voice-rescue   # Codex
```

Дальше просто попросите агента: *«почисти звук в interview.mp4»*, *«убери эхо с камеры»*,
*«сделай звук как с микрофона»*. Или запустите сами:

```bash
VR=~/.local/share/voice-rescue-src/skills/voice-rescue/scripts/voice-rescue
$VR doctor                       # что есть, чего нет
$VR install                      # модели: закреплённые версии, проверка sha256, докачка
$VR plan camera.wav --lang ru    # camera.wav: эхо (SRMR 5.9, OVRL 2.53), тихо (-40 LUFS) → Sidon → сведение
$VR process camera.wav --out cleaned/ --lang ru
```

## Что получается

Для каждой дорожки в папке результата:

- `<имя>.clean.wav`: 48 кГц, 24 бит, стерео с голосом по центру, −16 LUFS (настраивается), true peak
  не выше −1 dBTP, **той же длины и с того же момента, что исходник** (с точностью до сэмпла), если
  обрезку не просили;
- `report.md` простым языком (`--lang ru`): что было, что сделано, замеры до и после, какие гейты не
  прошли или не проверены, что отрезано;
- `metrics.json` со всеми замерами;
- `ab_before_30s.wav` / `ab_after_30s.wav`: одни и те же 30 секунд одинаковой громкости, чтобы решить ухом;
- `spectrogram_before.png` / `spectrogram_after.png`;
- `probe/` для длинных записей (самые трудные 2,5 минуты обрабатываются первыми) и
  `junction_probe.wav`, когда склеено несколько источников.

Несколько файлов одной съёмки (камера + запись экрана + петличка):
`process cam.mp4 screen.mov lav.wav --sync-to cam.mp4 --out session/`. Скилл по огибающей речи
проверяет, что они из одной сессии (своя ≈ 0,98, чужая 0,2–0,3), совмещает их до 1 мс без доверия
таймкодам и часам устройств, снимает дрейф часов, берёт лучший источник, заполняет его провалы
другими, подгоняет тембр и ставит стыки в паузы.

## Как устроено

```
анализ ─► маршрут ─► проба (трудные 150 с) ─► восстановление ─► выравнивание частей ─► тембр ─► сведение ─► проверка ─► доправка (≤3 кругов)
```

- **Восстановление: Sidon** (Токийский университет, MIT). Он не вычитает эхо, а заново собирает
  голос по признакам речи w2v-BERT 2.0, как будто его записали близким микрофоном, в 48 кГц.
  voice-rescue запускает его с нарезкой точной до сэмпла: исходный рецепт теряет 26 сэмплов на
  каждом куске по 96 с (5,6 млн⁻¹, около 20 мс в час — достаточно, чтобы уехать от картинки) и даёт
  задержку 7,4 мс; здесь исправлено и то и другое (см. [DECISIONS.md](DECISIONS.md), D5–D7).
- **Сведение**: срез ниже 70 Гц, лёгкий де-эссер, одно линейное усиление до цели, измеренной на
  итоговом стерео, мягкий лимитер с компенсацией задержки. Компрессора нет: он возвращает комнату.
- **Проверка**: все гейты ниже гоняются на отдаваемом файле. Непройденный гейт вызывает точечную
  доправку; после трёх кругов отдаётся лучший круг, а в отчёте сказано, что не прошло.

| Гейт | Проходит, когда |
|---|---|
| цель «подкаст-микрофон» | медиана по речевым окнам: DNSMOS OVRL ≥ 3,3, BAK ≥ 4,0 (SRMR показывается: он зависит от голоса, см. ниже) |
| не хуже входа | OVRL не ниже ни на одном окне; SRMR не ниже (для уже сухого входа — не ниже 9) |
| слова не изменились | уверенно распознанные слова входа на месте с поправкой на шум распознавания |
| голос тот же | сходство дикторских эмбеддингов вход/итог ≥ 0,65 |
| синхрон и длина | медиана сдвига ≤ 1 мс в 9 точках; длина точна до сэмпла |
| громкость | −16 ± 0,5 LUFS, участки в пределах ±1 LU, true peak ≤ −1 dBTP |
| тембр (с `--reference`) | средний спектр речи в третях октавы в пределах ±1 дБ от эталона |
| стыки, пропавшая речь | ни щелчка, ни скачка фона на стыках кусков и частей; нет речи входа, ставшей тишиной |

Каждый гейт проверен на нарочно испорченном итоге (добавленное эхо, сдвиг 50 мс, +3 LU, заменённое
слово, чужой голос, щелчок на стыке, скачок фона): он обязан упасть.

## Бенчмарк

Только открытая речь: 6 английских эталонов (LibriTTS-R test-clean, CC BY 4.0, их нет в обучении
Sidon) и 6 русских (чтецы LibriVox, общественное достояние); каждый испорчен по 12 классам
настоящими импульсными характеристиками комнат и шумами из OpenSLR 28 — 144 входа. Восемь движков (и две ветки-гипотезы)
прогнаны на всех, по одному, на процессоре. Медианы по классу; OVRL/BAK — DNSMOS (больше — лучше),
PESQ/ESTOI — против чистого оригинала, WER — против того, что тот же распознаватель слышит в чистом
оригинале, «голос» — сходство диктора с чистым оригиналом. Полная таблица:
[evals/results/bench.md](evals/results/bench.md).

| Класс | Вход OVRL | Sidon OVRL / BAK | Sidon PESQ / ESTOI | Sidon WER / голос | Лучший другой по OVRL (его WER) |
|---|---|---|---|---|---|
| чистая (повторяемость) | 3,42 | 3,45 / 4,18 | 2,70 / 0,89 | 0,01 / 0,91 | deepfilternet 3,45 (WER 0,00) |
| дальний микрофон, эхо | 1,84 | 3,46 / 4,21 | 2,00 / 0,79 | 0,06 / 0,86 | resemble-enhance 3,32 (WER 0,84) |
| дальний, эхо + шум комнаты | 1,62 | 3,50 / 4,21 | 1,98 / 0,77 | 0,08 / 0,85 | resemble-enhance 3,38 (WER 0,96) |
| как ноутбук (малая комната, полоса, AAC) | 2,42 | 3,49 / 4,20 | 2,07 / 0,74 | 0,06 / 0,85 | resemble-enhance 3,39 (WER 0,71) |
| сухой голос, сильный шум (5 дБ) | 2,37 | 3,51 / 4,21 | 2,05 / 0,84 | 0,08 / 0,82 | resemble-enhance 3,41 (WER 0,17) |
| клиппинг | 3,23 | 3,45 / 4,20 | 2,62 / 0,87 | 0,06 / 0,89 | sidon-declip 3,47 (WER 0,03) |
| телефон (300-3400 Гц, 8 кГц µ-law) | 3,32 | 3,46 / 4,19 | 2,34 / 0,89 | 0,03 / 0,77 | resemble-enhance 3,41 (WER 0,08) |
| MP3 24 кбит/с | 3,37 | 3,44 / 4,19 | 2,43 / 0,88 | 0,01 / 0,83 | resemble-enhance 3,41 (WER 0,05) |
| фон сети 50/60 Гц | 3,28 | 3,48 / 4,21 | 2,63 / 0,87 | 0,02 / 0,91 | sidon-notch 3,45 (WER 0,01) |
| очень тихо (-40 LUFS, 16 бит) | 3,37 | 3,43 / 4,19 | 2,70 / 0,89 | 0,01 / 0,91 | clearvoice 3,43 (WER 0,00) |
| цифровые обрывы | 3,26 | 3,36 / 4,17 | 1,91 / 0,84 | 0,03 / 0,89 | deepfilternet 3,33 (WER 0,04) |
| музыка под голосом | 2,71 | 3,49 / 4,21 | 2,31 / 0,85 | 0,00 / 0,90 | resemble-enhance 3,40 (WER 0,02) |

Что из этого следует:

- **Sidon — по умолчанию для всего, где есть комната** (дальний микрофон, эхо с шумом, ноутбук):
  DNSMOS OVRL около 3,5 из 1,6–2,4 при WER 0,06–0,08, впереди всех. Resemble Enhance для DNSMOS тоже
  *звучит* чисто (3,3–3,4), но говорит другое: WER 0,71–0,96, сходство голоса 0,55–0,63, и на
  процессоре он медленнее реального времени. VoiceFixer даёт 3,2 при WER 0,19–0,24 и изменённом голосе
  (0,68–0,70). DeepFilterNet и ClearerVoice убирают шум, а не комнату (2,3–3,0).
- **Чистый вход не трогается** (маршрут «только сведение»). По DNSMOS Sidon его не портит (3,45
  против 3,42), но пересобирает волну (PESQ 4,6 → 2,7), поэтому чистый близкий микрофон только
  сводится, если его не нужно склеивать с восстановленными частями.
- **Шум без комнаты**: Sidon чище по DNSMOS (3,51 против 3,34), а DeepFilterNet/ClearerVoice точнее
  сохраняют исходную волну (PESQ 2,6 против 2,1). Цель скилла — звук подкаст-микрофона, поэтому Sidon;
  классический шумодав не встроен.
- **Клиппинг, телефонная полоса, MP3 24 кбит/с, фон сети, очень тихо**: Sidon сам дотягивает до цели.
  Ветки-гипотезы (`adeclip` или режекция фона перед Sidon) — в таблице как `sidon-declip` /
  `sidon-notch`; ни одна не обошла Sidon без них (declip: OVRL 3,47 против 3,45, но PESQ 2,54 против
  2,62 и в 5 раз медленнее; режекция: 3,45 против 3,48), поэтому обе выключены
  (`--experimental declip,hum_notch` включает).
- **ONNX-порт Sidon** (soniqo/Sidon-ONNX, int8 и fp16) звучит так же, но на процессоре примерно в 2,5
  раза медленнее (0,37–0,40 от реального времени против 0,15); по умолчанию остаются веса TorchScript.
- **Музыку под голосом** восстановление убирает, а не сохраняет: DNSMOS оценивает итог как чистую
  речь — именно поэтому этот случай предупреждение, а не возможность.
- **Синхрон**: против чистых оригиналов выход Sidon стоит на медиане +0,1…+0,25 мс во всех классах
  (+1,0 мс с эхом и шумом); час речи держится в ±0,26 мс (`evals/results/sidon_drift.json`).

## Честно об ограничениях

- **Что доказано, а что экспериментально.** Путь по умолчанию (Sidon → сведение) проверен на
  настоящих записях (камера с эхом комнаты, встроенный микрофон ноутбука при записи экрана, петличка)
  и в бенчмарке выше. Экспериментальные ветки выключены по умолчанию, и план об этом говорит.
- **Голос пересобирается.** Sidon не вычитает комнату, а заново синтезирует речь по её признакам.
  Голос узнаётся (сходство диктора 0,87–0,95 на практике), но тембр может немного сдвинуться;
  `--reference` подгоняет его к дорожке, которая уже нравится.
- **Это замеры, а не прослушивание.** Гейты — приближение. Отчёт так и пишет и отдаёт пробы
  «до/после» по 30 секунд одинаковой громкости. Последнее слово за ухом.
- **Скорость.** Мерили только на процессоре: примерно в 5 раз быстрее реального времени на Apple
  M4 Max (20 минут записи — около 4 минут, час — около 13), плюс 1–3 минуты проверок. Веса для
  видеокарт (CUDA) есть, но в v0.1.0 не проверены.
- **Память.** Около 5 ГБ в пике (восстановление кусками по 30 с, декодер окнами по 3 с). Скилл
  проверяет свободную память до и во время работы и останавливается сам, а не загоняет компьютер в
  своп. Запускайте по одной задаче.
- **Диск.** Python-окружение около 1,0 ГБ, модели 1,5 ГБ (+1 ГБ необязательных весов CUDA, +1,6 ГБ
  необязательного большого распознавателя); кэш восстановления — около 0,7 ГБ на час звука, чтобы
  пересборка шла минуты; во время работы около 4 ГБ рабочего места на час звука.
- **Чего v0.1.0 не умеет.** Музыка под голосом (предупреждает, может её убрать или исказить), два
  голоса одновременно (не распознаёт), обрывы без второго источника (сообщает, но не латает),
  Windows (запускалка есть, не проверена).
- **Синхрон против очень гулкого входа** по огибающей до 1 мс не измерить (эхо размазывает вход);
  гейт тогда пишет «не проверен». Собственная точность движка доказана на синтетическом эхе и на часе
  речи (`evals/results/sidon_drift.json`).
- **Проверка слов.** Локальный Whisper small; его собственный шум вычитается, но на неанглийской
  речи он слабее. `--asr-model turbo` (1,6 ГБ) точнее.

## Разработка

```bash
uv run --project skills/voice-rescue --group dev ruff check skills/voice-rescue/src tests evals
uv run --project skills/voice-rescue --group dev pytest -q tests
```

CI на Linux и macOS гоняет линтер и быстрые тесты (синтетика и короткие открытые клипы); тесты,
которым нужны веса Sidon (1 ГБ), идут ручным workflow. Бенчмарк — в [evals/](evals/README.md).
